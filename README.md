# ユーコンシェルジュ トピックス検索

noteの記事(kuwaman_88)を一覧表示し、キーワードで絞り込める検索ページです。
記事データは **毎日自動で更新** されるので、noteに記事を足すだけで検索ページにも反映されます。

```
note ──(毎日自動で取得)──▶ GitHub ──(公開)──▶ 検索ページ(ユーコンシェルジュに貼る)
```

## 全体像と役割

| 担当 | やること | 頻度 |
|---|---|---|
| 記事の持ち主(GitHubを使う方) | このリポジトリのPagesを有効にして、最初の更新を1回動かす | **最初の1回だけ** |
| ユーコンシェルジュのUI担当の方 | `widget.html` の中身を貼り付ける | **最初の1回だけ** |
| 以後 | 何もしない。noteに記事を書けば、翌朝までに検索に出る | ― |

---

## 1. 公開の設定(記事の持ち主の作業)

### 1-1. GitHub Pagesを有効にする
1. リポジトリの **Settings → Pages** を開く。
2. **Source** を `Deploy from a branch` にする。
3. **Branch** を `main`、フォルダを `/docs` にして **Save**。
   (`docs` フォルダは最初の更新(1-2)で作られるので、先に1-2を行ってください)

### 1-2. 最初の更新を手動で動かす(必須)
記事データと検索ページを作り、データのURLをこのリポジトリの公開URLに設定するために必要です。
1. リポジトリの **Actions** タブを開く。
2. 「ワークフローを有効にする」のような確認が出たら、有効にする。
3. 左の **記事データを更新** を選び、**Run workflow** を押す。
4. 緑のチェックがつけば完了です(1〜2分)。

その後、1-1のPages設定を行います。

### 1-3. 動作確認
公開URL(`https://あなたのID.github.io/yuconcierge-note-search/`)を開いてください。
記事一覧が出て、検索窓で絞り込めれば成功です。

---

## 2. ユーコンシェルジュに貼る(UI担当の方へ)

1. リポジトリの `docs/widget.html` を開き、**Raw** ボタンを押して中身をすべてコピーする。
2. トピックス用のページ(B-Cartのフリーページ/HTML編集)の貼りたい位置に貼る。
3. 保存して、実際のページで検索できるか確認する。

メモ:
- 約11KBの小さなパーツです。記事データ(約1.4MB)は貼りません。GitHubから自動で読み込みます。
- ページ内で使うCSSは `#ycs-root` の中だけに限定してあるので、サイト全体のデザインには影響しません。
- 色は冒頭の `--g:#2e9e4f`(緑)です。サイトに合わせて変えられます。
- 何かの事情でデータの置き場所を変える場合は、貼ったコードの `var DATA_URL = "…"` のURLだけを書き換えます。
- トピックスのメニュー(今は note.com/kuwaman_88 に飛びます)のリンク先を、この検索ページに変えます。

## 3. 運用

### 記事を増やしたとき
何もしなくて大丈夫です。毎日 日本時間の朝6時ごろに自動で更新されます。
**すぐ反映したい場合**: Actions → 記事データを更新 → Run workflow。
反映後、ブラウザのキャッシュで最大10分ほど古い表示が残ることがあります。

### 言い換え・おすすめワードを増やしたい
`src/widget.template.html` の冒頭にある次の2か所を編集します。
- `SYN` … 左の言葉で検索したとき、右の言葉を含む記事もヒットさせる(例: `"いちご":["苺","ストロベリー"]`。逆向きにも効きます)
- `CHIPS` … 検索窓の下に出るワンタップ検索のワード

編集後、**Actions → 記事データを更新 → Run workflow** を1回動かすと `docs/widget.html` が作り直されます。
そのあと、UI担当の方にもう一度 `widget.html` を貼り替えてもらってください。

### noteのIDを変えたい
`.github/workflows/update.yml` の `NOTE_USER: kuwaman_88` を書き換えます。

### 検索に使う本文の長さ
初期値は記事の先頭1,500字です。増やすと精度は上がりますが、データが重くなります。
`.github/workflows/update.yml` の `env:` に `BODY_LEN: "3000"` のように足します。

## 4. 困ったとき

| 症状 | 確認すること |
|---|---|
| 検索ページに「記事データの読み込みに失敗しました」と出る | Pagesが有効か(手順1-1)/ 1-2の手動更新を一度やったか/ `widget.html` 内の `DATA_URL` がGitHub PagesのURLになっているか |
| 新しい記事が出ない | Actionsタブで最後の実行が緑か赤か。赤なら中身を開いてエラー内容を確認。手動で Run workflow して反映 |
| Actionsが動いていない | 公開リポジトリは60日間操作がないと定期実行が止まる仕様があります。この仕組みは止まらないように手当てしていますが、止まったらActionsタブから有効化し直してください(GitHubからメールも届きます) |
| 一部の記事の本文検索がうまくいかない | note側の取得に失敗した記事は、タイトルと冒頭の抜粋だけで検索されます。次回の更新で再取得されます |
| 記事を下書きに戻したり削除した | 翌日の更新で検索結果から消えます |

## 5. 補足

- 検索はすべてお客様のブラウザ内で行います。検索語がどこかに送信されることはありません。
- 検索対象は公開済みのnote記事のみです。有料記事・下書きは含まれません。
- 全角/半角、ひらがな/カタカナ、大文字/小文字の違いは区別せず、「いちご」「イチゴ」「苺」はどれでも同じ記事が出ます。
- このリポジトリのファイル構成:
  - `build.py` … noteから記事を取得して `docs/` を作る
  - `src/widget.template.html` … 検索ページの元
  - `docs/note-index.json` … 記事データ(自動生成)
  - `docs/widget.html` … ユーコンシェルジュに貼るパーツ(自動生成)
  - `docs/index.html` … 動作確認用ページ(自動生成)
  - `.github/workflows/update.yml` … 毎日の自動更新
